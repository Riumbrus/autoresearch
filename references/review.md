# Независимые проверки глубокого исследования

Авторитетная версия плана для проверки хранится в plan.md каталога прогона, версия итогового отчёта — в report.md. При передаче файла проверяющему предварительно вычисли SHA-256 точных байтов (в PowerShell: (Get-FileHash -Algorithm SHA256 -LiteralPath $path).Hash.ToLowerInvariant()). Зафиксируй значение в поручении вместе с путём; проверяющий сверяет его при чтении и возвращает с вердиктом. Для слепого приёмщика передай файл и хеш только во второй части, после фиксации самостоятельного ответа. Сохрани возвращённый хеш в reviews.<роль>.artifact_sha256. Для plan это хеш plan.md, для critique и acceptance — report.md. После изменения файла получи новые вердикты затронутых ролей. Не переноси старый вердикт на новый хеш. При возобновлении старого глубокого прогона без plan.md восстанови план из сохранённых материалов и проведи недостающие проверки до публикации «Завершено».

Координатор создаёт отдельного нового субагента на каждое назначение без истории родительского чата (в Codex: fork_turns="none", в Antigravity: новый вызов invoke_subagent). Передай ограничения проекта и доступа, перечисли разрешённые для чтения файлы. Запрети поиск истории чата и чтение соседних рабочих материалов. Общая файловая система доступна агентам: ограничение входа задаётся поручением. Каждый проверяющий получает только материалы своего этапа. Освобождай занятые слоты между этапами. Дословные ответы, реальные ID исполнителей и входные материалы с версиями фиксируй в notes.md. После возобновления используй результаты только для той версии плана или выводов, которую проверяли.

1. **Проверяющий плана (plan).** Передай исходный запрос, описание доступных данных и план. Попроси сопоставить каждый вопрос пользователя с проверкой, назвать существенное упущение и проверить, различимы ли альтернативные объяснения. Устрани замечания до выдачи зависимых участков. Изменённый по существу план передай свежему проверяющему.
2. **Критик выводов (critique).** Передай запрос, черновик, разрешённые первичные источники и воспроизводимые расчёты. Попроси самостоятельно воспроизвести определяющее число или проверить ключевую цитату, проверить наиболее сильную альтернативу и указать условие закрытия каждого существенного замечания. Локальную ошибку исправляет автор, ошибку метода разбирает новый аналитик с чистым контекстом. На повторную проверку назначь нового критика; передай изменённый вывод, источники и условия закрытия.
3. **Слепой приёмщик (acceptance).** Передай только исходный запрос и разрешённые источники. Не передавай план, гипотезы команды, notes.md, снимки состояния, report.md или расчёты автора. Получи самостоятельный ответ с основаниями и ограничениями, запиши его до раскрытия черновика. Затем в том же контексте покажи версию отчёта и попроси сопоставить ответы. При существенном расхождении исправь вывод или явно сохрани спор рядом с ним. После существенной правки повтори приёмку с другим новым агентом, начиная со слепого шага.

Сохраняй в draft.json объект reviews с ключами plan, critique, acceptance. Для актуальной проверки каждого этапа запиши agent (реальный ID), verdict («Принято» или «Открыто») и result (содержательный вывод и основание). Для acceptance сохрани также blind_answer из первого ответа. После изменений, затрагивающих проверку, пометь её «Открыто» до перепроверки. Старые попытки остаются в notes.md. Если отдельный агент недоступен или существенное расхождение осталось, укажи этап и ограничение в report.md и итоговом сообщении, опубликуй «Частично». Не засчитывай самопроверку за независимый вердикт.
