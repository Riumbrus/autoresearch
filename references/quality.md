# Проверки количественного исследования

## Исходные данные — Pandera

Для повторяющейся выгрузки сохрани согласованную схему рядом с расчётом. Укажи ключ, типы, допустимые пропуски и ограничения, применимые к единице наблюдения. При наличии Pandera выполни schema.validate(frame, lazy=True) и сохрани сводку нарушений с номерами строк. Образец для денежной маржи — tests/margin_schema.py. Без библиотеки выполни те же проверки средствами имеющейся среды. Отрази их фактический результат до передачи данных исследователям.

## Зависимости расчёта — подход DVC

Для каждого существенного расчёта по локальным файлам помести в draft.json запись calculations с полями id, inputs, parameters, command, result. inputs — словарь «путь относительно каталога прогона или абсолютный путь → SHA-256 байтов». Включи срез данных, сам скрипт или SQL и применённую схему. Запиши параметры, команду воспроизведения и результат; свяжи ID расчёта с выводом в evidence. Хеши фиксируй при расчёте. publish повторно проверяет их при финальной публикации. При изменении входа пересчитай затронутые выводы и верни их критику. Для живого SQL зафиксируй время, параметры и доступный воспроизводимый срез. Если проект уже ведёт dvc.lock, используй его сведения о стадиях и включи файл в зависимости. Описание формата: https://github.com/treeverse/dvc .

## Устойчивость вывода — подход specr

До просмотра результатов перечисли обоснованные способы расчёта и вопрос, на который отвечает каждый. Например, для маржи портфеля сравни прибыль / выручку при фактическом составе продаж и взвешенную маржу по SKU с весами выручки базового периода. Зафиксируй базу, периоды и обращение с новыми или исчезнувшими SKU. Приведи результат каждого варианта и объясни смену знака. Передай критику весь набор вариантов, включая расходящиеся. Для расширенного перебора моделей в имеющейся R-среде подходит https://github.com/masurp/specr .

## Оценка версий навыка — Inspect AI

Контрольная таблица — tests/fixtures/margin.csv. Передай новому чату только исходный файл и вопрос «Как изменилась маржа?». Сохрани ответ до открытия эталона. Проверь отдельно арифметику, чувствительность к весам и границы вывода. Если нужно проверить роли, используй журнал реального прогона: текст ответа не подтверждает независимость критика. Для сравнения модельных ответов по числам в среде с Inspect AI доступна команда inspect eval tests/inspect_margin.py --model <модель>. Этот тест оценивает модель на таблице; сквозная проверка навыка требует отдельного запуска агента. Оценочный набор можно расширять независимыми задачами. Эталон: фактическая маржа 18% → 26% (+8 п.п.), при весах первого периода 18% → 14% (−4 п.п.). Внутри обоих SKU снижение на 4 п.п.; причина изменения структуры продаж по этим строкам неизвестна.
